# rulebook

## Goal

You write a rule once, and no Agent's work breaks it again. Every decision in rulebook passes three tests:

- **Agents know the rules before they write.** An Agent sees every rule that covers the file, reply, or inbox item it's about to write, and follows them from the start.
- **Every write is checked before it lands, and as fast as possible.** A broken rule refuses the write with the flagged line. The fastest check that can catch a mistake is the one that catches it, because a faster check means a faster Agent loop and better software.
- **A rule graduates from narrow to broad.** A rule starts in the narrowest scope that needs it, and graduates to a broader one once it proves true beyond it. So a lesson one project learns reaches every project it fits, and no project works out the same lesson again.

# Facts

rulebook lints Claude Code Prompts. The `rulebook` program checks a Prompt, and any other file or message a rule's `paths` cover, against static and agentic rules, and the rulebook mod asks the one `rulebook serve` on the computer before every Edit, Write, and MultiEdit, before the main agent's turn ends, and before each tool call a registered message's `tools` match, so an error refuses the edit, the stop, or the call.
